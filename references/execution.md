# 归集、签名与无人值守

仅在任务涉及资金执行、其实现或专项审查时读取。本参考不授予真实交易权限，也不证明项目代码已经过资金测试。

## 规则与授权

先形成可检查的规则：来源钱包范围、网络、收款地址、币种允许列表、原生币保留量、归集门槛、费用预算，以及是否撤哪些协议的 LP。若有无人值守，还要明确运行周期、暂停方式和重启策略。

- 代码可先实现；缺少目标地址、必要限额或签名能力时保留预览，禁止广播。
- 不把“可以开发自动归集”视为“现在转走全部资产”。用户明确启动已展示的规则，或会话已明确授权该规则执行时，在范围内继续，不重复逐笔询问。
- 规则发生实质变化后不要悄悄沿用旧预览；校验规则版本和执行范围。
- 资产发现列表不是转出允许列表。原生币数量门槛、每币种门槛与法币价值门槛是不同含义；无价格来源不能实施美元阈值。
- 补 gas 是额外的资金转移，需要资金来源、预算和对应授权。用户没要求补 gas 时，余额不足的操作跳过。

## 签名隔离

浏览器管理公开地址、规则及任务；后端校验交易；本地签名组件只处理授权范围内的签名。不要在聊天或网页里要求用户粘贴私钥，不把私钥写进进程命令行、日志、错误响应和生成文档。

Windows 的用户绑定 DPAPI 是本地凭证保存的一种实现。凭证应由用户在自己的终端隐藏输入并加密保存，服务在同一 Windows 用户环境解密。另一个受限进程解密失败时，不降级为明文文件，也不要求用户把秘密发给助手。仅在已有授权和环境允许的情况下调整运行权限。

DPAPI 加密不等于保护私钥不受同一用户权限下的恶意进程影响。其他操作系统或托管场景按现有密钥管理方案实现，不强制使用 Windows 脚本。向前端只返回“是否配置”，不返回凭证内容或存储路径。

## 执行前重新核对

余额看板是快照，不能直接当作可签名交易。

1. 检查规则仍有效，签名公钥与来源匹配，网络正确，来源与目标不同；拒绝明显不可用的收款地址，并按目标链区分地址有效与可收款。
2. 读取当前余额、仓位所有权和待处理交易。按钱包与链串行控制 nonce；发现外部待确认交易时不能靠重试覆盖。
3. 为本轮尚未执行的代币、LP 操作保留手续费。通常先解除相关质押/撤 LP，再归集代币，最后归集原生币；若协议能直接将底层代币收取到目标，可省去中间转账。
4. 使用真实交易结构模拟及估费。ERC-20 返回 false 应视为失败；标准允许的空返回需要兼容处理，但查询余额的空返回不作零。
5. L2 费用区分执行费和适用的数据费；Solana 还可能有优先费及目标代币账户租金。估算上限和绝对实际费用上限不是同一保证，界面应说明语义。
6. 撤 LP 核对协议、版本、tokenId、实时 liquidity、截止时间及最低接收量。不能直接采用无限滑点或把不同协议套同一调用。
7. 未适配 Token-2022 扩展、transfer hook、冻结状态或特殊代币行为时，明确阻止相关执行，而不是因为余额查询成功就认为转账兼容。

执行代码、ABI 和地址来自项目/官方来源时仍需验证。不得盲目复用本案例的部署地址、默认手续费或旧模拟结果。

## 先记账，再广播；未知状态不重发

推荐根据实际执行器维护等价的状态流：

`planned → checked → signed/pending → confirmed | reverted | unknown`

- 在广播前持久化可恢复的交易标识、来源、目标、规则版本及 EVM nonce / Solana 所需确认上下文。不要把私钥持久化进交易日志。
- 超时不等于交易失败。广播结果不明、回执缺失时标记 unknown，暂停该钱包链上的冲突操作；简单单队列应用也可暂停整个执行队列。
- 重启后先核对链上回执和 pending 状态，不根据“本地没有完成记录”直接再发一笔。多进程/实例时增加互斥，不能仅依靠前端禁用按钮。
- 使用同一已签名交易重广播、替换 nonce 或判定区块哈希过期属于显式恢复策略；未实现策略时保持待核对，不能无限重试或生成新转账。
- 暂停只能阻止后续动作，不能撤回已广播交易。界面说明当前操作何时让出执行。
- 对本地工具，自动执行默认关闭、重启后需要重新启动是一种稳妥默认。若用户明确要求重启续跑，应实现恢复核对后再续跑，不静默改变需求。

## 验证证据分层

| 验证 | 能支持的结论 | 不能支持的结论 |
| --- | --- | --- |
| 地址、整数、规则、排序测试 | 对应逻辑在所测条件下符合预期 | 所有代币或协议都兼容 |
| Mock / 本地链故障注入 | 网络、nonce、余额及持久化异常路径行为 | 真实链上的经济结果正确 |
| 链上只读请求 | 特定端点和已覆盖查询可用 | 签名、转账、撤 LP 已实盘验证 |
| static call / simulateTransaction | 指定状态下的模拟结果 | 广播后一定成功、无价格变化 |
| 已授权的小额端到端交易 | 该链、资产、协议版本及条件下的实测结果 | 所有网络、资产和大额交易均安全 |

特别测试广播超时但链上已成功、落盘后进程崩溃、钱包存在 pending nonce、任务重复启动、规则变化、费用不足和 LP 所有权变化。未经授权不通过真实转账“补齐测试”。
